## Core Style

Linux Mascot images are sparse 16:9 horizontal article illustrations where Tux performs one cognitive action inside an original physical article metaphor.

## Must Have

- 16:9 horizontal article illustration by default.
- White or very light background with generous whitespace.
- Rough black hand-drawn linework with visible looseness.
- One core idea per image.
- Tux performs the core conceptual action.
- Limited route colors: black and white for Tux, yellow-orange for beak and oversized webbed feet, and restrained red, orange, or blue accents only when they clarify the article action.
- Sparse readable visible labels, usually 2-6 total, copied exactly in the user's requested language.
- Supporting objects selected for the current article idea.
- Tux recognition stays clear inside the simplified drawing style.

## Composition

- Use a single visual structure: Workflow, System Local View, Before/After, Character State, Concept Metaphor, Method Layers, Map Route, or Mini Comic.
- Make Tux's action physically readable: inspect, point, carry, sort, bridge, repair, guide, stamp, mark, tune, shield, weigh, connect, untangle, map, compare, lift, assemble, or route.
- Use article-metaphor props sparingly: maps, bridges, knots, compasses, shelves, lamps, shields, stamps, keys, gates, scales, envelopes, source cards, license tags, review stamps, small terminals as abstract props, and small hand-built machines.
- Treat supporting objects as article metaphors for judgment, review, handoff, hidden coupling, failure mode, decision gates, framing, sequencing, prioritization, trust, source context, or conceptual repair.
- Leave empty space around Tux's action so the metaphor reads at a glance.
- Keep labels short and separated from Tux's eyes, beak, belly, flippers, and oversized yellow-orange webbed feet.
- Linux Mascot cognitive-action participation gate: Tux performs the core cognitive action, so the image loses its meaning if Tux is removed.
